1. Vue globale

SIMTIS reçoit les relevés des banques et les écritures de Sage, les met dans un format commun, puis calcule la position bancaire, propose les rapprochements, prépare les écritures de frais et présente le tout dans un tableau de bord.

SourcesRelevés Excel des 5 banques (AWB, BMCE, BP, CIH, BMCI) · export Sage / SI (grand livre des comptes de banque)
▼
IntégrationAssistant d'import en 2 étapes · détection des colonnes · contrôles · doublons · opérations en cours
▼
NormalisationFormat standard à 11 champs · dates, montants, sens · pointage automatique · soldes calculés
▼
TraitementsPosition bancaire · Rapprochement (moteur + validation humaine) · Frais bancaires · (Prévisions à venir)
▼
PilotageDashboard Suivi / Indicateurs · alertes · rapports Excel · export Sage des frais · lettrage
▼
UtilisateursTrésorerie · Comptabilité · Responsable · Direction · Administrateur
Règles transverses. Une seule société affichée à la fois (Simtis ou Tefil, choisie dans l'en-tête). Deux devises ne sont jamais additionnées. Le moteur propose, l'humain valide. Toute action sensible est tracée.

4. Sources et intégration des données

Relevés bancaires

Fichiers Excel (.xlsx, .xls) propres à chaque banque, jusqu'à 50 000 lignes. Opérations en cours : dans le relevé (BP, « (*) ») ou en fichier séparé (BMCE, CIH).

Export Sage / SI

Grand livre des comptes de banque, par société. Seules les lignes banque des journaux de banque sont gardées. Colonne « Devise » pour les comptes EUR / USD.

Principe commun aux deux imports

ChoixCompte (relevé) ou société (Sage) + fichier
›
AnalyseRien n'est écrit
›
AperçuValides, erreurs, doublons, ignorées
›
Choix des lignesCases à cocher
›
ConfirmationContrôle refait par le serveur, enregistrement, audit

Le modèle de colonnes est mémorisé (par banque pour les relevés, par société pour Sage) et complété automatiquement si une colonne apparaît. L'écran de mapping n'apparaît que si des colonnes ne sont pas reconnues.

5. Module Relevés bancaires

5.1 Import

  1. Choisir le compte (liste avec logos) et déposer le fichier : l'analyse démarre seule.
  2. Étape Validation : le relevé tel qu'il sera enregistré, au format standard, modifiable ligne par ligne ; tuiles de filtre ; solde d'ouverture proposé (modifiable seulement au premier import du compte) ; soldes calculés en gris.
  3. Confirmer : les lignes cochées sont enregistrées, la clôture devient le solde du jour du compte, un contrôle de solde est enregistré.

5.2 Consultation

  • Un relevé continu par compte, en ordre chronologique, avec résumé (ouverture, mouvements, clôture), période et recherche.
  • Modifiables après import : Pointage (liste des 74 catégories), Lettrage / Escompte, Commentaire.
  • Colonne « Code rapprochement » ; export Excel du relevé ou de la période.

6. Module Écritures Sage

  • Prérequis : chaque compte a ses journaux Sage et son compte comptable (écran Comptes).
  • Import par société ; une case « Importer » par ligne ; une ligne en erreur se corrige dans Sage.
  • Liste des écritures : 50 par page, filtres compte, dates, statut, sens, recherche (libellé, pièce, code de rapprochement), totaux sur tout le filtre, colonne Devise.
  • Les écritures de frais créées par SIMTIS apparaissent avec l'origine « SIMTIS » ; leur retour dans un export Sage est reconnu comme doublon.

12. Administration, historique et paramètres

  • Utilisateurs : création (mot de passe à usage unique affiché une fois), modification, rôles, activation / désactivation, réinitialisation. Un administrateur ne peut ni se désactiver ni retirer son propre rôle d'administrateur ; il reste toujours un administrateur actif.
  • Rôles : matrice des permissions, rôles personnalisés, suppression d'un rôle sans utilisateur.
  • Paramètres : points des critères, tolérance de date, fenêtres (normale, même numéro, élargie), seuils de proposition et « forte » ; modèles de colonnes mémorisés.
  • Historique : journal de toutes les actions sensibles, filtrable par utilisateur, action, objet et date, avec le détail avant / après.

13. Journées types

Trésorerie

  1. Supprimer les opérations en cours du compte (BP, BMCE, CIH).
  2. Importer les relevés du jour de chaque banque, puis les fichiers d'opérations en cours.
  3. Vérifier les pointages « À choisir ».
  4. Saisir les soldes des comptes sans relevé et le crédit utilisé.
  5. Lire la Position bancaire et le dashboard (dépassements de ligne).

Comptabilité

  1. Importer l'export Sage de la période.
  2. Lancer le rapprochement (et la recherche élargie au besoin).
  3. Valider les propositions fortes, examiner les autres, trancher les ambiguës.
  4. Valider les frais bancaires proposés, passer les autres à la main, exporter pour Sage.
  5. Exporter le lettrage et les frais > 200 DH pour la banque.

14. Cycle de vie des données

ObjetCycle
Opération bancaireImportée (Non rapprochée, ou En cours) → À vérifier (proposition) → Rapprochée (validation) ; retour à Non rapprochée après rejet ou annulation ; suppression possible seulement si en cours et libre.
Écriture SageImportée → À vérifier → Rapprochée ; jamais modifiée dans SIMTIS.
CorrespondanceProposée → Validée (code) ou Rejetée (jamais reproposée) ; Validée → Annulée (motif, code conservé).
Écriture de frais SIMTISProposée (calculée) → Validée (écriture + rapprochement) → Exportée ; suppression possible avant export.
Journée de fraisProposée → Écartée (motif) → Reproposée.
Traçabilité. Chaque transition ci-dessus écrit une ligne dans le journal d'audit (qui, quand, avant, après), consultable dans Historique.
