**Accounting balance** (decision of 26/10/2026, migration 0039: `bank_accounts.date_solde_comptable`, `solde_comptable_ouverture`, `solde_comptable_ouverture_devise`, CHECK `solde_comptable_date`; `services/solde_comptable_service.py`): solde comptable = opening balance entered once per account at a date (the Sage general ledger, debit = positive) + débits − crédits of the account's entries **after** that date up to the chosen date (`accounting_repository.mouvements_comptables`; Sage, SIMTIS fee and manual entries all count, SIMTIS entries not yet exported are counted apart, `nb_non_exportees`); an EUR / USD account also gets its balance in its currency (opening in that currency required, minus the signed `montant_devise`); without an opening only the movements are given (`solde` null, never a 0 start). `GET /api/accounting/soldes?company_id=&date=&bank_account_id=` (read permission of the entries; active accounts with a Sage journal) also returns the statement balance at the same date (`soldes_par_compte` + `solde_connu`) and `ecart` = bank − book in the account's currency; `PUT /api/accounting/soldes/{id}/ouverture` (`accounting.import`, all null clears it, audit `solde_comptable_ouverture`). Screen: « Solde comptable » card at the top of `/ecritures` (`SoldeComptableCard`, date picker, one row per account, pencil opens the opening-balance form); **collapsed by default** (title button with a chevron, last choice kept in `localStorage` key `simtis.ecritures.solde-comptable` through `lib/repli.ts`, read with `useSyncExternalStore`; nothing is requested from the API while collapsed).

**P10 (done, spec `docs/superpowers/specs/2026-10-05-import-sage-design.md`)**: Sage / SI exports are imported per company on `/ecritures` (`POST /api/accounting/import/analyse` and `/confirm`, permission `accounting.import`; reading `GET /api/accounting/entries` (50 per page, newest first, filters account / dates / status / `q`, totals over the whole filter), `/entries/{id}`, `/imports`, with `accounting.import` OR `reconciliation.view`). Each bank account carries its **Journaux Sage** (`bank_accounts.journal_sage`, migration 0010; since 12/10/2026 **several journals per account**, stored as « 5243,5543 », typed « 5243, 5543 » in the Comptes screen, migration 0022: the partial unique index is replaced by the trigger `bank_accounts_journaux_uniques`, a journal belongs to one active account per company; `account_service.journaux_sage`; BP uses 5243 for encaissements and 5543 for frais, commissions and remboursements, 9000 = à-nouveaux, never a bank journal); only the **bank line of a bank journal** is kept (journal = an account's Journal Sage, account starting with its `compte_comptable`), other lines are counted as ignored; débit / crédit stay as in Sage; no correction in SIMTIS (an error line is fixed in Sage or unchecked); **checkboxes** (decision of 08/10/2026): the preview has an « Importer » box per line and `/confirm` takes `lignes_choisies` (JSON line numbers, only those are imported; a checked error or already-imported line gives 409, a checked internal duplicate is imported; since 29/10/2026 the Validation tile « Total débit / crédit » covers the **checked** lines only, computed on screen in exact cents, `importLines.totauxCoches`; **since 03/11/2026** instead of the file's solde it shows, per account of the file, the **solde comptable après import** at the file's last date: the analysis sends in `par_compte` `date_solde`, `date_ouverture` and `solde_avant` (the « Solde comptable » card's rule without the file, `accounting_import_service._soldes_avant_import`; null without an opening or when the opening is dated after the file) and the screen adds the checked lines of that account dated after the opening (`importLines.soldesApresImport`, MAD for every account, « solde d'ouverture à saisir » rather than a start at 0; the Sage balance of the file is not read); mixing it with the older `garder_doublons` / `ecarter_erreurs` gives 422); duplicates by line hash per company; the column mapping is remembered per company (`column_mappings.company_id`); since 09/10/2026 a saved model is **completed by the detection** for the fields it does not know (`import_file.mapping_from_headers`, statements too), so a column added to the export (Échéance, N° pièce) is no longer ignored, and « N° de pièce(s) » / « Pièces » are recognised. File reading (sheet, header, columns, synonyms) is shared with statements in `services/import_file.py`.

**Changes of 27/10/2026** (no business-side samples were given for the PDFs): (1) **several comptes comptables per bank account** (migration 0041: `bank_accounts.compte_comptable` 20 → 200 characters, typed « 51410000, 51410100 », stored « 51410000,51410100 », at most 9, `account_service.comptes_comptables` / `compte_principal`): the Sage import keeps a line whose account starts with **any** of them; SIMTIS fee entries use the **first** one; a manual entry (`ManualEntryModal`, field `compte` of `POST /api/accounting/entries`) chooses one when there are several (409 otherwise).

**Reprise of the Sage due date** (decision of 04/11/2026, no migration, `services/echeance_service.py`): the AWB general ledger titles its due-date column with a date (31/12/2025) instead of « ECH », so the import did not read it and the AWB entries have no `echeance`. `python -m app.cli completer-echeances --societe SIMTIS --fichier F [--colonne-echeance J] [--colonne journal=C …] [--feuille …] [--appliquer --motif … --email …]` (simulation without `--appliquer`) reads the file through `accounting_import_service.analyse_entries` (company model, plus the due-date column: the given letter, else the only column titled by a date; `--colonne champ=LETTRE` forces a column the model does not know, e.g. `compte=A --colonne journal=C` for the AWB titles « compt » / « journale »), finds each entry by its `hash_ligne` (which does not contain the due date) and fills only an empty `echeance`; a different due date already there is kept and reported, a file line without entry is only listed; one transaction, audit `completer_echeance` per entry. The Sage import itself is unchanged: the next AWB GL needs its column titled « ECH » or a manual mapping. The rapprochement is not re-run: pending proposals keep their score until the next « Lancer le rapprochement ».
